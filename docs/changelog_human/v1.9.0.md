## 新增

- **发布策略重构**：release-please 改为仅创建 Release PR 和 CHANGELOG，不再自动打 tag、不再自动触发发布流水线。只有人类明确执行 `git tag vX.Y.Z && git push origin vX.Y.Z` 才触发正式发布构建，避免"一合并就发布"绕过人类审查的风险。
- **changelog.html 自动生成**：新增 `tools/generate_changelog_html.py`，从 `docs/changelog_human/*.md` 自动生成人类友好的网站变更页内容。Release PR 合并后由 `post-merge-stamp` 自动调用，无需手动维护 HTML。支持 `make changelog`（重建）和 `make changelog-check`（CI 检查）两个 Makefile 目标。
- **PR 模板版本影响说明**：`.github/PULL_REQUEST_TEMPLATE.md` 新增版本影响表，明确 `feat:`/`fix:`/`chore:` 各前缀对版本号的影响，避免因前缀选择不当触发意外版本升级。
- **PR 标题规范校验**：新增 `.github/workflows/pr-title-check.yml`，强制 PR 标题遵循 Conventional Commits 规范（squash-merge 用 PR 标题作为 commit message，release-please 据此分类生成 CHANGELOG）。
- **变更日志覆盖检查**：`generate_changelog_html.py --verify-coverage` 对照 CHANGELOG.md 报告缺少人类友好条目的已发布版本，确保网站变更页不会静默遗漏版本。

## 变更

- `release-please.yml`：添加 `skip-github-release: "true"`；post-merge-stamp job 在 stamp 后额外调用 `generate_changelog_html.py` 重建网站变更页。
- `docs/RELEASE-CHECKLIST.md`：更新为新的手工 tag 触发发布流程，包含完整的操作命令。
- `docs/VERSIONING.md`：更新发布策略描述，说明手工 tag 触发机制。
- `AGENTS.md`：更新 Release Process 章节，新增 changelog_human 格式规范和手动发布命令。
